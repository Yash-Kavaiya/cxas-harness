Engines

Lint engine

cxas lint --app-dir <path> loads the app tree, builds a LintContext, and runs every registered rule. Diagnostics are collected into a LintReport and printed as JSON (or human text).

How to run

cargo run -p cxas-cli -- lint --app-dir ./my-app
cargo run -p cxas-cli -- --format human lint --app-dir ./my-app

Any error-severity diagnostic makes the process exit 1. Missing app.yaml / app.json fails V001.

Structural rules

IdCheck
V001app.yaml, app.yml, or app.json exists at the app root
V002display_name is non-empty
V003every agents/<name>/ directory contains instruction.txt or agent.yaml
V004every tool referenced by an agent exists under tools/
V005tool schema JSON is a valid JSON Schema object (draft 2020-12 shape)
V006evaluation files reference existing agents
V007instruction.txt must not be empty when present
V008agent display names must be unique
V009environment.json boolean fields must be JSON booleans, not strings

Additional generated structural/schema variants bring the registry past 60 rule ids (Phase 3 completeness vs schema). RuleRegistry::ids() is the live list.

llm-lint

Semantic review uses crates/cxas-lint/prompts/semantic_review.txt and a Gemini HTTP client. Build with --features llm. Without that feature the CLI exits 2 with a disabled-feature code.

App skeleton init writes

my-app/
  app.yaml
  agents/
    main/
      instruction.txt

That tree is enough for V-ROOT and V001-V003 to pass if app.yaml points root_agent at main.
