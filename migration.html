Migration

cxas-migration converts a Dialogflow CX agent into a CXAS app and keeps eval-run snapshots from leaking. The default path is non-interactive.

CLI

cargo run -p cxas-cli -- migrate dfcx \
  --source ./dfcx-export \
  --zip ./agent.zip \
  --project-id my-project \
  --location us \
  --target-name migrated \
  --yes

--yes confirms the pipeline without a prompt (required under --no-input).

Pipeline

  1. Read a DFCX export directory or zip (MigrationSource)
  2. Build an IrBundle (flows, playbooks, tools, traces)
  3. Resolve flow dependencies
  4. Write a MigratedApp for the MigrationTarget

Supporting types include DFCXAgentExporter, FlowDependencyResolver, ConversationTrace, and graph visualizers. They run in-process against fixtures in this checkout.

SnapshotGuard (#168)

Hillclimb used to leave agent snapshots behind on panic or cancel. SnapshotGuard implements RAII:

  • On drop it deletes every snapshot it created
  • Panic and cancel take the same path
  • take_failed_deletes reports snapshots the API failed to delete so callers can retry

The guard talks to a SnapshotApi trait. Tests inject a fake API; there is no Cloud call here.

ToolSync (#394)

When a tool disappears on the remote tree, local tools/ must drop it too. ToolSync diffs content hashes from cxas-state and returns a SyncReport.

TUI

An interactive migrator exists behind the tui feature. Default builds stay non-interactive so CI and coding agents never block on a terminal UI.
