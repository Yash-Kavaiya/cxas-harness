Reaching CES: cxas api

The rest of this binary works on a checked-out app directory and its .cxas state. cxas api is the other half: every method CES declares, addressed by its discovery id.

Generic rather than one subcommand per method, because there are 170 of them and a hand-written verb for each would add a spelling to remember and nothing else. What a caller genuinely cannot do unaided is discover the ids, know which surface declares them, and see which parameters a path needs -- so list and describe do exactly that, offline.

cxas api list --filter evaluationRuns
cxas api describe ces.projects.locations.apps.get

cxas api call ces.projects.locations.apps.list \
  --param parent=projects/my-project/locations/us-central1 \
  --query pageSize=25

cxas api stream ces.projects.locations.apps.sessions.streamRunSession \
  --param session=projects/my-project/locations/us-central1/apps/demo/sessions/s1 \
  --body '{"query":"hello"}'

Errors that arrive before the request does

CodeWhen
MISSING_PARAMETERA path template variable was not supplied. Named locally, so the answer is the parameter rather than a 404 from CES.
UNKNOWN_METHODNo such method. If the id exists on the other surface -- every evaluation method is v1beta-only -- the error says so instead of guessing.
NOT_STREAMINGapi stream on a method that returns a single response.
USAGEA malformed --param, or a --body that is not valid JSON.
AUTHNo usable credential, or one that cannot be turned into a token.
CESThe service answered non-2xx. Its own message is preserved.

Credentials

Resolved the way Google's own tools resolve them, highest precedence first:

SourceNotes
--oauth-tokenUsed verbatim; never refreshed
CXAS_ACCESS_TOKENThe CI escape hatch
GOOGLE_APPLICATION_CREDENTIALSAuthorized-user files only
Well-known ADC file~/.config/gcloud/, or %APPDATA%\gcloud\ on Windows
Metadata serverGCE, Cloud Run, GKE
gcloud auth print-access-tokenThe ordinary local-dev path

Tokens are cached and refreshed a minute before expiry, so a long-running process neither fails mid-flight nor mints a token per request.

An unusable credential at a higher precedence is an error rather than a reason to fall through. If GOOGLE_APPLICATION_CREDENTIALS points at a service-account key -- which needs signing this workspace does not do -- authenticating as the developer instead would send the request as the wrong principal, and the resulting 403 would point at the wrong problem.

Location-bearing flags

Most CES-shaped commands accept:

--location <id>
--project-id <id>

Omitting --location on those commands is a usage error (exit 2, code LOCATION_REQUIRED).
