Limits and honesty

This page exists so nobody mistakes a passing workspace test suite for a production CES client.

What works now

  • Full Cargo workspace, 221 Rust tests and 77 Python tests passing, clippy clean
  • All 170 CES REST methods addressable, from a table generated out of Google's discovery documents and checked against them in both directions
  • Application Default Credentials: environment token, authorized-user file, metadata server, or gcloud — cached and refreshed before expiry
  • Server streaming: streamRunSession delivered message by message, with truncation reported rather than rounded down
  • cxas api list / describe / call / stream — the live surface, with offline discovery of what exists
  • Every CLI verb in the parser dispatches and returns a JSON envelope
  • Local catalog persistence across processes
  • Location newtype: no Default, and no resource name can be built without one
  • Lint registry, eval cursor/DTMF/audio scorers, snapshot RAII, tool sync — in-process
  • actions init writes workflow files from templates
  • Gauntlet builder/blind-critic loop under gauntlet/, tested against a stub agent

Addressable is not modelled

Two coverage numbers are reported, and the gap between them is the honest description of this checkout:

CountWhat it means
Addressable170 / 170Generated. A request can be built, signed, and sent, and the response returned verbatim.
Modelled37 / 170Hand-written. This workspace has a type for the resource and an opinion about what its failures mean.

Generating 170 path templates is cheap. Deciding what a Deployment is, and what should happen when promoting one fails halfway, is not. Collapsing the two into a single figure would be the kind of flattery this project was built to avoid.

The benchmark, and what it caught

The API benchmark is Google's own CES discovery documents, vendored under reference/ces/ at pinned revision 20260806: 66 methods in v1, 104 in v1beta, verified by sha256 against PINNED.toml.

On its first run that contract found a real defect. EvaluationRunState declared PENDING/SUCCEEDED/FAILED where CES declares QUEUED/COMPLETED/ERROR — the test closing the enum-drift bug (#284) had itself drifted, invisibly to 78 passing tests. The previous parity contract could not have caught it: it asserted that a checked-in YAML contained strings that same YAML declared.

What this checkout does not do

SurfaceReality
Typed request and response bodiesBodies are JSON in, JSON out. Only 37 methods have a Rust type behind them; the other 133 hand you the raw document.
Catalog commandscreate, push, apps list and friends still read and write .cxas/catalog.json. cxas api is the live path; the catalog verbs have not been moved onto it.
Service-account keysNot implemented — needs RS256 JWT signing. A key file is refused by name, with the supported alternatives listed, rather than silently falling through to another identity.
Workload identity federationNot implemented — needs an STS token exchange. Same explicit refusal.
Long-running operationsAn Operation is returned as-is. No polling, no wait-for-completion helper.
Retries and backoffNone. A 429 or 503 is returned as a typed error; the caller decides.
Bidirectional streamingServer streaming works. True bidi (client and server talking at once) is not offered by the REST surface and is not implemented here.
deploy / migrateLocal catalog + pipeline fixtures. No Cloud deploy job.
Vertex STT / Gemini llm-lintSTT is a trait. llm-lint needs --features llm and a real key you supply later.
run-sessionRequires a TTY. Not for CI.
Issue-to-test linkageThe coverage map says all 25 cataloged issues have closing tests, and that mapping lives only in a markdown table. Of the 25, 3 have a test whose body actually cites the issue number; the other 22 are linked by prose alone. The Gauntlet evidence bundle now reports this per issue rather than asserting the claim.
Gauntlet builder isolationThe design specified a per-piece git worktree. It was never built, and the claim has been withdrawn rather than left standing: the builder edits your working tree, so run it on a branch. Out-of-scope edits are at least reported to the critic as paths.
GauntletImplemented under gauntlet/, never shipped in the binary. Not yet run against a live model.
Reference-drift CIWritten, staged at docs/ci/reference-drift.yml, not installed. Installing it needs a token with the workflow scope.

Never verified against a live project

Every test in this repository runs against loopback stubs and vendored documents. That is a deliberate trade: it makes the suite deterministic, offline, and honest about what it checks. It also means no request in this codebase has been answered by CES itself. The URLs, verbs, and enum spellings match Google's own machine-readable description of the API — which is a strong claim, and a different claim from "this works against production".
