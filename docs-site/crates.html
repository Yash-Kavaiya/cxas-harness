Product

Crate SDK

The cxas binary is a thin dispatcher. Library crates own types, rules, and tests. Depend on the crate that owns the behavior you need.

cxas-parity

Loads parity/cxas-scrapi-parity.yaml. The manifest pins the Python module/class/method surface at commit 4f7b43ca6adda0acad95a7e3654eee4e2ed1438c of GoogleCloudPlatform/cxas-scrapi and names the Rust owner crate for each type.

cxas-proto

EvaluationRunState with variants Unspecified, Pending, Running, Succeeded, Failed, Cancelled, and Unknown(i32).

  • from_wire(i32) never panics on a new CES value
  • as_str_name() returns UNKNOWN(n) for unknown integers -- it does not call .name on a raw int (#284)
  • build.rs generates from proto/ces/evaluation_run_state.proto when protoc is present; otherwise the hand-written wrapper is used

cxas-core

Public exports include:

  • Location -- mandatory newtype, no Default
  • Apps, AppName -- list/get/create/delete/export (streamed ExportHandle, --version-id)
  • Deployments, Deployment, ChannelSettings -- noise cancellation and channel type (#403)
  • Evaluations, QuotaKind -- dedicated RunSession quota (#263)
  • ClientConfig, Credentials
  • CesTransport, NoopTransport, RecordingTransport
  • METHODS, MethodSpec, method_spec — the CES methods this crate implements, verified against discovery
  • AppRef, LocationRef — typed resource names; neither can be built without a Location
  • RequestBuilder, RestRequest, expand_path — pure request construction
  • CesHttpClient — live REST client, unary and streaming (rest feature)
  • TokenProvider — ADC credential resolution, caching, refresh
  • METHODS — all 170 CES methods, generated from discovery
  • MODELLED — the 37 this workspace models with its own types

cxas-utils

  • Pagination helper for CES-style page tokens
  • render_environment / TemplateValue::Bool so environment.json booleans stay JSON booleans, not "true" strings (#256)

cxas-state

  • hash_app_dir / StateHash / AppTree -- content-addressed tree
  • diff_trees / StateDiff -- cxas diff (#131)
  • resolve_workspace -- cascading profiles from cxas.workspace.yaml (#270)
  • Errors include path escape, profile cycle, missing active profile, location required

cxas-evals

  • TurnCursor / UserInput -- advances past the first static_utterance (#355)
  • BidiSession / CesBidi -- DTMF wait-or-timeout (#345)
  • AudioScorer, SpeechPathScorer, HttpStt, require_audio (#27, #136, #188)
  • SimulationEvals, TurnEvals, ToolEvals, CallbackEvals, GuardrailEvals
  • TurnRow + combined HTML/JSON report (#206)

cxas-lint

  • RuleRegistry::builtin()
  • Named rules V-ROOT, V-WELCOME, V-DEPVER, schema rules, structural V001-V009
  • Optional LlmLintClient behind the llm feature

Full rule table: Lint engine.

cxas-migration

  • SnapshotGuard -- deletes hillclimb snapshots on drop, panic, or cancel (#168)
  • ToolSync -- cloud tool deletion reflected locally via state hash (#394)
  • MigrationPipeline -- DFCX export -> IR -> CES app, non-interactive by default
  • Optional MigrationTui behind tui

cxas-cli

Clap parser in args.rs, dispatch in commands/, JSON writer in output.rs, catalog in catalog.rs. Integration tests live under crates/cxas-cli/tests/.
