What this project is

cxas-harness is an independent Rust rewrite of Google Cloud's cxas-scrapi. It is a CLI (cxas) plus nine workspace crates. Design work followed Superpowers specs and plans dated 2026-08-15 under docs/superpowers/.

cxas-core speaks the real CES REST surface: 35 of 170 methods are declared and verified against Google's vendored discovery documents, with an HTTP client behind the rest feature. The CLI still reads and writes .cxas/catalog.json; wiring the commands onto the live client is the next phase. Tests never require a cloud project. Location is never silently defaulted to "global" — every CES path template embeds projects/*/locations/*, so a resource name cannot be built without one.

Machine-first CLI

JSON envelope on stdout, --no-input on by default, exit codes 0 / 1 / 2. Built for coding agents and CI.

Mandatory Location

Location has no Default. Empty is an error. __default_global__ is rejected. The literal "global" is allowed only when the caller passes it.

Issue-driven tests

The 25 cataloged cxas-scrapi issues each have a closer in the coverage map and an in-process unit test.

Nine crates

Parity, proto, core, utils, state, evals, lint, migration, and the cxas binary.

Honest status

144 workspace tests pass (150 with --features cxas-core/rest). cxas-core can issue real CES requests, but the CLI commands still record or read .cxas/catalog.json rather than calling it. Bidi streaming and Vertex STT are not implemented. See Limits and honesty.
