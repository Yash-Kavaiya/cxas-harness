Architecture

Operators and coding agents talk only to the cxas binary. The binary delegates to workspace crates. Live CES and Vertex sit on the other side of a transport trait that this checkout implements with mocks.

Location newtype

cxas_core::Location is a newtype around String with no Default impl.

  • Location::new("") and whitespace-only -> CoreError::LocationRequired
  • Location::new("__default_global__") -> CoreError::LocationHardcodedGlobalForbidden
  • Location::new("global") succeeds
  • Location::new("us"), "europe-west1", and other regional IDs succeed

This is the compile-time and runtime closer for blocker #401 (hardcoded vertex_location = "global" in Python).

Transport seam

cxas_core::CesTransport is the interface for CES RPCs. Implementations in this checkout:

TypeUse
NoopTransportDefault in-process stub. Export and mutate calls succeed with empty or fixture payloads.
RecordingTransportCaptures requests for tests (export stream, version-id, channel settings).

A future live transport would implement the same trait and talk to CES. The CLI already goes through this seam for pull, deploy, and app export.

CLI I/O contract

Designed for issue #55 (CLI ergonomics for coding agents):

  • Default --format json
  • --no-input defaults true so the process never blocks on stdin
  • Stdout is one JSON object per invocation (Envelope)
  • Exit 0 success, 1 runtime/lint/eval/drift, 2 usage/TTY/feature

Quality bar

Acceptance is dual: (a) the Phase 0 parity manifest's types and CLI argv are owned by crates, and (b) every cataloged issue has a closing unit test named in the plan. See Issue coverage.
